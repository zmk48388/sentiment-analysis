## 2. 화면 상태 4가지

화면은 항상 아래 4가지 중 **정확히 하나**의 상태입니다. 상태를 바꾸는 함수를 하나(`setState`)로 만들어 모든 전환을 거치게 하세요.

| 상태 | 언제 | 입력창 | 분석하기 버튼 | 결과 카드 | 오류 박스 |
|---|---|---|---|---|---|
| `idle` (대기) | 처음 / 지우기 후 | 사용 가능 | 활성화 | 숨김 | 숨김 |
| `loading` (분석 중) | 요청 보낸 직후 ~ 응답 전 | **읽기 전용** | **비활성화**, 라벨 "분석 중..." | 숨김 | 숨김 |
| `success` (성공) | 정상 응답 | 사용 가능 | 활성화 | **표시** | 숨김 |
| `error` (오류) | 입력 오류 / 요청 실패 | 사용 가능 (입력 내용 **유지**) | 활성화 | 숨김 | **표시** |

- 새 분석을 시작하면(`loading`) 이전 결과와 이전 오류는 **반드시 지웁니다.**
- 숨김은 HTML의 `hidden` 속성으로 처리합니다.

## 3. 동작 상세

### 3-1. 입력과 글자 수 (FR-1)
1. 입력할 때마다(`input` 이벤트) `#char-count`를 `현재글자수 / 500` 형태로 갱신합니다. (예: `12 / 500`)
2. 글자 수 기준은 입력값 그대로의 길이(`value.length`)입니다. 서버 검사는 앞뒤 공백을 뺀(`trim`) 길이로 하므로, 화면 표시와 약간 달라도 정상입니다.
3. 450자 초과: `.char-count`에 `is-warning` 클래스 추가 (색 변경 — `docs/02` 참고). 450자 이하로 돌아오면 제거.
4. `textarea`에 `maxlength="500"`이 있어 500자를 넘길 수 없지만, **붙여넣기 등으로 우회될 수 있으므로** 제출 시 다시 검사합니다.

### 3-2. 분석 요청 (FR-2)
제출 방법은 두 가지이며 동작은 동일합니다.
- "분석하기" 버튼 클릭 (폼 `submit` 이벤트, `event.preventDefault()` 필수)
- 입력창에서 **Ctrl+Enter 또는 Cmd+Enter** (`#analyze-form.requestSubmit()` 호출)

처리 순서:
1. 이미 `loading` 상태면 **아무것도 하지 않고 종료** (중복 요청 방지)
2. `text = textarea.value.trim()`
3. **화면 쪽 검사**
   - 비어 있으면 → `error` 상태, 메시지 `EMPTY_INPUT` (서버 호출 안 함)
   - 500자 초과면 → `error` 상태, 메시지 `INPUT_TOO_LONG` (서버 호출 안 함)
4. `loading` 상태로 전환
5. `fetch('/api/analyze', { method: 'POST', headers: {'Content-Type': 'application/json'}, body: JSON.stringify({ text }) })`
6. 응답 처리 (3-3, 3-4)
7. 어떤 결과든 마지막에 로딩 상태를 해제 (`try / catch / finally` 사용)

### 3-3. 성공 응답 처리 (FR-3, 4, 5)

서버 성공 응답(HTTP 200) 형식:
```json
{ "sentiment": "positive", "confidence": 87, "reason": "맛과 서비스에 대한 만족 표현이 분명합니다.", "saved": true }
```

화면 반영 규칙:

| 대상 | 규칙 |
|---|---|
| 배지 글자 | `positive`→`긍정`, `negative`→`부정`, `neutral`→`중립` |
| 배지 색 | `#result-badge`의 `data-sentiment` 속성에 `positive` / `negative` / `neutral` 설정 |
| 신뢰도 숫자 | `${confidence}%` (예: `87%`) |
| 신뢰도 막대 | `#confidence-fill`의 `style.width = ${confidence}%`, `data-sentiment`도 동일하게 설정 |
| 분석 이유 | `#result-reason.textContent = reason` |
| 낮은 신뢰도 안내 | `confidence < 60` 이면 `#low-confidence-note`의 `hidden` 제거, 아니면 숨김 |
| `saved` 값 | **화면에 표시하지 않음.** (검증/디버깅용이므로 무시) |

**응답 검증(방어적 처리):** 서버가 약속한 형식이 아니면 (sentiment가 3가지가 아님, confidence가 0~100 숫자가 아님, reason이 문자열이 아님) 결과를 표시하지 말고 `INVALID_AI_RESPONSE` 오류로 처리합니다.

성공 후 결과 카드가 화면 밖에 있으면 `scrollIntoView({ behavior: 'smooth', block: 'nearest' })`로 보이게 합니다. (`prefers-reduced-motion` 설정 시 `behavior: 'auto'`)

### 3-4. 오류 처리 (FR-6)

오류는 두 곳에서 생깁니다: (가) 화면 쪽 검사, (나) 서버/네트워크.

**서버가 오류를 돌려줄 때**(HTTP 200이 아님) 응답 형식:
```json
{ "error": { "code": "OPENAI_ERROR", "message": "..." } }
```
→ 화면은 서버의 `message`를 쓰지 않고, **아래 표의 문구를 `code`로 찾아** 표시합니다. (문구를 한곳에서 관리하기 위해)
→ `code`가 표에 없거나 응답이 JSON이 아니면 `INTERNAL_ERROR` 문구를 표시합니다.

**`fetch` 자체가 실패할 때**(인터넷 끊김 등, `catch`로 들어옴) → `NETWORK_ERROR` 문구를 표시합니다.

#### 오류 문구 표 (이 문구 그대로 사용)

| code | 어디서 | 화면에 표시할 문구 |
|---|---|---|
| `EMPTY_INPUT` | 화면/서버 | 분석할 문장을 입력해 주세요. |
| `INPUT_TOO_LONG` | 화면/서버 | 500자 이하로 입력해 주세요. |
| `INVALID_REQUEST` | 서버 | 요청 형식이 올바르지 않아요. 페이지를 새로고침한 뒤 다시 시도해 주세요. |
| `METHOD_NOT_ALLOWED` | 서버 | 잘못된 접근이에요. 페이지를 새로고침한 뒤 다시 시도해 주세요. |
| `RATE_LIMITED` | 서버 | 요청이 많아요. 잠시 후 다시 시도해 주세요. |
| `OPENAI_TIMEOUT` | 서버 | 분석이 오래 걸리고 있어요. 잠시 후 다시 시도해 주세요. |
| `OPENAI_ERROR` | 서버 | AI 분석 중 문제가 생겼어요. 잠시 후 다시 시도해 주세요. |
| `INVALID_AI_RESPONSE` | 화면/서버 | 분석 결과를 이해하지 못했어요. 다시 시도해 주세요. |
| `INTERNAL_ERROR` | 서버/기본값 | 알 수 없는 오류가 발생했어요. 잠시 후 다시 시도해 주세요. |
| `NETWORK_ERROR` | 화면 전용 | 네트워크 연결을 확인하고 다시 시도해 주세요. |

- 오류가 표시되어도 **입력창의 내용은 지우지 않습니다.** 사용자가 바로 다시 시도할 수 있어야 합니다.
- 오류 박스는 `textContent`로 문구를 넣습니다.
- 오류가 표시될 때 입력창으로 포커스를 돌려주지는 않습니다. (스크린리더가 `role="alert"`로 읽어줍니다.)

### 3-5. 예시 문장 (FR-11)
- `.sample-btn` 클릭 시: 버튼의 `data-text` 값을 입력창에 채우고, 글자 수를 갱신하고, 상태를 `idle`로 만듭니다(이전 결과/오류 지움).
- **자동으로 분석을 실행하지 않습니다.** 사용자가 "분석하기"를 눌러야 합니다.
- 입력창에 포커스를 줍니다.

### 3-6. 지우기 (FR-12)
- 입력창 비우기, 글자 수 `0 / 500`, 상태 `idle`, 결과/오류 숨김, 입력창에 포커스.
- `loading` 중에는 "지우기" 버튼을 **비활성화**합니다. (분석 도중 화면이 꼬이는 것 방지)

### 3-7. 로딩 상태 (FR-7)
- 버튼 라벨: `분석하기` ↔ `분석 중...`
- 버튼에 `disabled` 속성, `aria-busy="true"`를 설정 (끝나면 제거)
- 별도의 스피너 이미지는 쓰지 않습니다. 라벨 텍스트 변경으로 충분합니다. (필요 시 CSS로 점 3개 애니메이션은 허용)
- 화면 쪽 대기 시간 제한: `AbortController`로 **25초** 후 요청을 중단하고 `OPENAI_TIMEOUT` 문구를 표시합니다. (서버 제한 20초보다 길게)

## 4. 감성 판단 기준 (AI에게 전달할 기준, 화면 쪽은 참고용)

| 값 | 의미 | 예시 |
|---|---|---|
| `positive` (긍정) | 만족, 기쁨, 칭찬, 기대 등 좋은 감정이 **뚜렷** | "정말 맛있어요!" |
| `negative` (부정) | 불만, 슬픔, 분노, 실망 등 나쁜 감정이 **뚜렷** | "너무 실망했어요." |
| `neutral` (중립) | 감정 표현이 없는 사실 전달이거나, 긍정·부정이 섞여 한쪽이 뚜렷하지 않음 | "회의는 3시에 시작합니다." |

- 판단 규칙의 최종 위치는 `docs/04-api-spec.md`의 시스템 프롬프트입니다. 화면은 판단하지 않고 **결과를 표시만** 합니다.

## 5. 코드 구조 가이드 (`app.js`)

아래 함수 단위로 나누세요. (이름은 그대로 사용 권장)

| 함수 | 역할 |
|---|---|
| `getElements()` | 필요한 HTML 요소를 한 번에 찾아 객체로 반환 |
| `setState(state, payload)` | 4가지 화면 상태 전환 (모든 화면 변경은 여기서) |
| `updateCharCount()` | 글자 수 표시 갱신 |
| `validateInput(text)` | 화면 쪽 입력 검사 → 오류 code 또는 `null` |
| `requestAnalysis(text)` | `fetch` 호출, 성공 데이터 반환 / 실패 시 `{code}`를 가진 오류를 throw |
| `renderResult(data)` | 성공 결과를 화면에 반영 (3-3) |
| `renderError(code)` | 오류 문구 표 조회 후 표시 (3-4) |
| `handleSubmit(event)` | 제출 처리 전체 흐름 (3-2) |
| `handleSample(event)` / `handleReset()` | 예시/지우기 |
| `init()` | 이벤트 연결, 초기 상태 설정 |

- 전역 변수 최소화: 파일 전체를 `(() => { ... })();` 로 감싸거나 `init` 안에서 관리합니다.
- 상수는 파일 맨 위: `MAX_LENGTH = 500`, `LOW_CONFIDENCE = 60`, `CLIENT_TIMEOUT_MS = 25000`, `ERROR_MESSAGES = {...}`

### 가짜 데이터(mock) 단계 (AGENTS.md 8번 단계 3)
서버가 없는 단계에서는 `requestAnalysis`가 아래처럼 임시 응답을 돌려주게 만들어 4가지 화면을 확인합니다. **서버 연결(단계 6)에서 mock 코드는 완전히 제거**합니다.

| 입력에 포함된 단어 | 임시 응답 |
|---|---|
| "맛있" | `positive`, 92 |
| "실망" | `negative`, 88 |
| "오류테스트" | 오류 `OPENAI_ERROR` 던지기 |
| "낮음" | `neutral`, 45 |
| 그 외 | `neutral`, 70 |

mock은 `const USE_MOCK = true;` 한 줄로 켜고 끌 수 있게 하고, 최종 제출 시에는 `USE_MOCK` 코드 블록이 **없어야** 합니다.

## 6. 구현 범위 / 제약 조건

**범위:** 위 FR-1~7, 11, 12의 브라우저 동작
**제약:**
- 순수 JavaScript만 사용 (`fetch`, `AbortController`, DOM API)
- 사용자 입력/서버 응답은 **`textContent`로만** 화면에 넣음 (`innerHTML` 금지)
- `localStorage`, 쿠키에 입력 내용을 저장하지 않음
- 브라우저에서 OpenAI/Supabase 주소를 직접 호출하지 않음 (호출 대상은 `/api/analyze` 하나)
- 분석 기록 목록 표시, 공유, 복사 기능 추가 금지
