# 06. 배포 및 최종 검증 지침

> 목표: Vercel에 배포하고, **모든 요구사항이 실제로 동작하는지** 체크리스트로 확인합니다.
> 이 문서의 체크리스트를 모두 통과해야 `AGENTS.md`의 "완료 기준"을 만족합니다.

## 1. 배포 전 점검 (로컬에서 먼저)

| # | 점검 | 방법 | 기대 결과 |
|---|---|---|---|
| 1 | 로컬에서 전체 흐름 동작 | `npx vercel dev` → 화면에서 분석 | 결과 표시 + Supabase 행 생성 |
| 2 | mock 제거 | `public/js/app.js`에서 `USE_MOCK` 검색 | 0건 |
| 3 | 비밀 키 노출 없음 | 아래 명령 실행 | 결과 없음 |
| 4 | `.env`가 Git에 없음 | `git status`, `git ls-files \| grep -i "^.env"` | `.env.example`만 나옴 |
| 5 | `README.md` 작성 | 파일 확인 | 설치/환경변수/로컬 실행/배포 방법 포함 |

키 노출 점검 명령:
```bash
grep -rniE "sk-[A-Za-z0-9]|service_role|OPENAI_API_KEY|SUPABASE_SERVICE" public/
# 아무것도 출력되지 않아야 정상
git log -p | grep -E "sk-[A-Za-z0-9]{10,}" 
# 아무것도 출력되지 않아야 정상 (과거 커밋에도 키가 없어야 함)
```
> 위 명령에서 실제 키 값이 출력되면 **즉시 작업을 멈추고** 사용자에게 알린 뒤, 해당 키를 폐기(재발급)하도록 안내합니다.

## 2. Vercel 배포 절차

사용자 계정 작업이 필요한 단계는 **사용자가 직접** 하고, 에이전트는 쉬운 말로 안내합니다.

| 순서 | 할 일 | 담당 |
|---|---|---|
| 1 | GitHub에 새 저장소 만들기 (Private 권장) | 사용자 |
| 2 | 로컬 프로젝트를 GitHub에 올리기 (`git remote add origin ...`, `git push`) | 에이전트(사용자 확인 후) |
| 3 | [vercel.com](https://vercel.com) 로그인 → **Add New → Project** → GitHub 저장소 선택 → Import | 사용자 |
| 4 | **Framework Preset: Other** 로 설정. Build Command, Output Directory는 **비워둠**. (`public/` 폴더는 자동으로 정적 파일로 서빙됨) | 사용자 (에이전트가 안내) |
| 5 | **Environment Variables**에 4개 입력: `OPENAI_API_KEY`, `OPENAI_MODEL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (Production, Preview 모두 체크) | 사용자 |
| 6 | **Deploy** 클릭 | 사용자 |
| 7 | 배포 완료 후 발급된 주소(`https://프로젝트명.vercel.app`) 접속 | 사용자 + 에이전트 |

주의:
- 환경변수를 **배포 후에 추가/수정**했다면 **재배포(Redeploy)** 해야 반영됩니다.
- Vercel 환경변수 입력 칸에는 값만 붙여넣고, 따옴표(`"`)나 앞뒤 공백을 넣지 않습니다.
- 배포 후 `public/index.html`이 `/`에서, `/api/analyze`가 서버 함수로 동작해야 합니다. 둘 중 하나라도 404면 폴더 구조(`public/`, `api/`가 프로젝트 **최상위**에 있는지)부터 확인합니다.
- `vercel.json`의 `maxDuration` 때문에 배포가 실패하면 오류 메시지 원문을 사용자에게 보고하고, 요금제 한도 이내 값으로 조정합니다.

## 4. 최종 검증 체크리스트

**모든 항목을 직접 실행해서 확인**하고, 보고서에 통과(✅)/실패(❌)와 확인 방법을 적습니다.
"코드를 읽어보니 될 것 같다"는 통과 근거가 아닙니다.

## 5. 실패 시 대응

| 증상 | 먼저 확인할 것 |
|---|---|
| 배포 주소에서 `/api/analyze`가 404 | `api/analyze.js`가 프로젝트 최상위 `api/` 폴더에 있는지 |
| 화면은 뜨는데 분석 시 `INTERNAL_ERROR` | Vercel 환경변수 4개가 모두 입력됐는지, 입력 후 재배포했는지 (Logs에서 없는 변수 이름 확인) |
| `OPENAI_ERROR` | OpenAI 키가 유효한지, 결제/사용 한도 상태, `OPENAI_MODEL` 이름 오타 |
| `OPENAI_TIMEOUT` | OpenAI 응답 지연 여부, 모델 선택, `maxDuration` 설정 |
| `INVALID_AI_RESPONSE` | 구조화 출력 설정(JSON Schema)이 올바른지, 모델이 지원하는지 |
| 결과는 나오는데 `saved: false` | Supabase URL/키 오타, `schema.sql` 실행 여부, 테이블 이름 |
| 한글이 깨져 보임 | `index.html`의 `<meta charset="UTF-8">`, 파일 저장 인코딩(UTF-8) |

해결하지 못하면 **오류 메시지 원문, 시도한 방법, 의심되는 원인**을 사용자에게 보고하고 질문합니다. (AGENTS.md 6번)
